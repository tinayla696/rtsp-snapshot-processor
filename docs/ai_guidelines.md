# AI ガイドライン

このリポジトリを読む AI エージェントは、以下の制約と意図を優先してください。

## 互換性ルール

- Python 3.10 互換性を維持すること。
- TOML 読み込みは `tomllib` を直接前提にせず、`tomli` フォールバックを壊さないこと。
- 依存追加時は `requirements.txt` とドキュメントの両方を更新すること。

## 例外処理ルール

- 一時的なディスクエラー、DB ロック、設定読み込みミスでプロセス全体を落とさないこと。
- 保存・登録系の失敗は `logging.exception` または `logging.error` で記録し、可能なら次周期へ継続すること。
- 起動時の設定不備は、無意味な traceback ではなく、利用者が修正できるメッセージに変換すること。

## 状態管理ルール

- 共有状態はスレッドセーフに扱うこと。
- `FrameReceiver` の最新フレームはロック付きで更新・取得する前提を守ること。
- `SnapshotRepository` の SQLite 接続は、複数箇所から無制御に触らないこと。
- 新しい共有キャッシュやバッファを追加する場合は、データ競合と停止時の解放順序を明示すること。

## 設計ルール

- 受信、保存、永続化、起動管理の責務を混ぜないこと。
- 既存のクラス境界を壊す前に、まず既存の責務に沿った拡張を考えること。
- GPU デコードや AI 推論を追加する場合でも、`FrameReceiver` と `SnapshotService` の境界は維持すること。
- ローカル環境差分がある前提で、利用手順と設定例を更新すること。

## テスト観点

- 保存成功時に JPEG が生成され、DB に絶対パスと `status=True` が入ること。
- 保存失敗時に DB へ `status=False` が入ること。
- 設定ファイルの欠落、破損、CLI 上書きが期待どおり動くこと。
- GStreamer が有効な環境と無効な環境の両方を意識して回帰を防ぐこと。
